<h2 id="language-map">შექმენით ენის ვერსიების რუკა</h2>

<p>პირველ ცხრილში დააკავშირეთ ყველა ენის გვერდები. მაგალითად, ქართული სერვისის გვერდი შეიძლება ინგლისურ გვერდს შეესაბამებოდეს, მაგრამ ყველა გვერდს ზუსტი წყვილი არ ექნება. მონიშნეთ:</p>

<ul>
  <li>ძველი URL და ენის კოდი;</li>
  <li>ახალი URL და გვერდის სათაური;</li>
  <li>თარგმანი დასრულებულია, რედაქტირდება თუ საერთოდ არ არსებობს;</li>
  <li>ვინ ამოწმებს იურიდიულ, კომერციულ და ტექნიკურ ტერმინებს;</li>
  <li>რომელ გვერდებზეა ფორმა, CTA, სურათი ან ჩამოსატვირთი ფაილი;</li>
  <li>რომელი ძველი URL უნდა გადამისამართდეს და რომელს სჭირდება ახალი ტექსტი.</li>
</ul>

<p>არ შექმნათ ცარიელი თარგმანის გვერდი მხოლოდ იმიტომ, რომ ენის მენიუში ღილაკი არსებობს. თუ ენის ვერსია ჯერ არ არის მზად, მომხმარებლის გზა და საძიებო სისტემის სიგნალი მკაფიოდ უნდა იყოს განსაზღვრული.</p>

<h2 id="url-architecture">URL-ის არქიტექტურა</h2>

<p>Google-ის საერთაშორისო ძიების დოკუმენტაცია გირჩევთ განსხვავებულ URL-ებს განსხვავებული ენის ან რეგიონის შინაარსისთვის. ეს შეიძლება იყოს ენის პრეფიქსი, ქვედომენი ან სხვა მკაფიო სტრუქტურა. არჩევანი პროექტის არქიტექტურაზეა დამოკიდებული, მაგრამ სხვადასხვა ენის გვერდი ერთსა და იმავე URL-ზე შემთხვევითი გადართვით არ უნდა დარჩეს.</p>

<p>შეინარჩუნეთ ენის სტრუქტურა ყველა შიდა ბმულში. თუ ქართული გვერდი ახალ მისამართზე გადავიდა, ქართულ მენიუში ის ქართულ ვერსიას უნდა მიუთითებდეს. ინგლისურ გვერდზე კი ინგლისური რესურსები უნდა გამოჩნდეს. URL-ის რუკა დაუკავშირეთ <a href="/blog/wordpress-migration-seo-redirect-checklist">გადამისამართებების ჩეკლისტს</a>. შეცვლილი URL-ისთვის მუდმივი 301 ან 308 გადამისამართება ცალკე უნდა დაიგეგმოს.</p>

<h3 id="hreflang">hreflang-ის სწორი კავშირი</h3>

<p>Google-ის რეკომენდაციით, ენის ვერსიებმა ერთმანეთს hreflang სიგნალით უნდა მიუთითონ. თითოეულ ვერსიას სიაში საკუთარი მისამართიც უნდა ჰქონდეს და დანარჩენი შესაბამისი ვერსიებიც. ბმულები შეიძლება განთავსდეს HTML-ში, HTTP სათაურში ან საიტის რუკაში, მაგრამ ერთი მეთოდი თანმიმდევრულად გამოიყენეთ.</p>

<p>სიგნალი მხოლოდ მაშინ არის სასარგებლო, თუ მითითებული URL რეალურად იხსნება, საკუთარ თავს მიუთითებს და გვერდის ენა ემთხვევა მის აღწერას. შეცდომების სია შეავსეთ მინიმუმ ამ ველებით: გვერდი, ენა, hreflang კოდი, მითითებული URL, პასუხის სტატუსი და შემოწმების თარიღი.</p>

<h3 id="translation-quality">თარგმანის ხარისხის 3 შემოწმება</h3>

<ol>
  <li><strong>მნიშვნელობა:</strong> სერვისის პირობები, მოქმედება და შეზღუდვა ორ ენაზე ერთნაირად არის გაგებული;</li>
  <li><strong>ტერმინები:</strong> ბრენდის სახელები, იურიდიული სიტყვები, პროდუქტის სახელები და CTA შეთანხმებულად იწერება;</li>
  <li><strong>ქმედება:</strong> ფორმა, ტელეფონი, ელფოსტა, კალენდარი და გადახდის ან მოთხოვნის გზა რეალურად მუშაობს შესაბამის ენაზე.</li>
</ol>

<p>ქართული ტექსტის ბუნებრიობა ცალკე უნდა შემოწმდეს. პირდაპირი მანქანური თარგმანი შეიძლება გრამატიკულად წაკითხვადი იყოს, მაგრამ ბიზნესის პირობებში არასწორი ტონი ან მნიშვნელობა დატოვოს. თარჯიმანი ან ენის პასუხისმგებელი უნდა ხედავდეს არა მხოლოდ ფრაზას, არამედ გვერდის მიზანსა და მოქმედებას.</p>

<h3 id="content-model">კონტენტის მოდელი და მედია</h3>

<p>WordPress-ის Export ინსტრუმენტი ჩანაწერებსა და გვერდებს XML/WXR ფორმატში ამოიღებს, მაგრამ მრავალენოვანი კავშირები, მედიაზე დამოკიდებულებები და პლაგინის სპეციფიკური ველები ცალკე შესამოწმებელია. მიგრაციამდე ჩამოწერეთ რომელი ველი ინახავს ენის კოდს, თარგმანის წყვილს, slug-ს, alt ტექსტს და SEO აღწერას.</p>

<p>სურათის ალტერნატიული ტექსტი ენის მიხედვით უნდა აღწერდეს იმავე ვიზუალურ ფუნქციას. ჩამოსატვირთი დოკუმენტები, ფორმის დამადასტურებელი შეტყობინება და შეცდომის ტექსტიც თარგმანის გეგმის ნაწილია. ხელმისაწვდომობისთვის ეს საკითხები კონკრეტულ შემოწმების კრიტერიუმებთან შეადარეთ.</p>

<h3 id="scenario">სცენარი: ქართული და ინგლისური სერვისები</h3>

<p>წარმოიდგინეთ ქართული მომსახურების კომპანია, რომელსაც ქართული და ინგლისური გვერდები აქვს, მაგრამ ახალი სერვისები ჯერ მხოლოდ ქართულად ქვეყნდება. ძველ საიტზე ენის მენიუ ყველა გვერდს აკავშირებს, მათ შორის ცარიელ ინგლისურ URL-ებსაც.</p>

<p>გუნდმა ჯერ ადგენს რომელი სერვისებია ორივე ბაზრისთვის აქტიური და რომელი ტექსტი ჯერ არ არის დამტკიცებული. მიგრაციისას მზადდება ცალკე URL-ები მხოლოდ დასრულებული ვერსიებისთვის, hreflang კავშირი მოწმდება ორივე მიმართულებით და ენის მენიუ აჩვენებს რეალურ ხელმისაწვდომობას. ინგლისურ გვერდზე ფორმის მიმღები და ავტომატური პასუხი ცალკე ტესტირდება, რადგან ერთი ენის ტექსტის გამართვა მეორე ენის პროცესს არ ამტკიცებს.</p>
